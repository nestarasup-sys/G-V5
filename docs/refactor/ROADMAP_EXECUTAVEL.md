# Roadmap executável, gates e checklists

**Versão:** 2026-10-18, base `5b848345`. **Esta é a única fonte de verdade para tarefas e progresso.** Evidência e classificação dos fatos estão em [INVENTARIO_E_EVIDENCIAS.md](INVENTARIO_E_EVIDENCIAS.md). Nada abaixo foi implementado nesta revisão. O plano é incremental: cada PR/commit deve deixar `typecheck`, build e casos afetados verdes antes de avançar.

## Contrato obrigatório por tarefa

Para fechar qualquer `R-xx`: registrar **problema**, `E-xx`/arquivo/linha, hipótese, comportamento esperado, mudança mínima, tipos de tarefa, pré-requisitos, impacto em outras features, risco, fallback/rollback, esforço **P/M/G** (pequeno ≤1 dia; médio 2–4 dias; grande ≥5 dias, estimativa qualitativa a recalibrar), **critério verificável**, ambiente, comando executado, SHA, duração, resultado e link para artefato de teste. Falta de prova => **aberto**; falha => bloqueia próxima etapa.

**Gates globais:** dados reais intocados sem backup e autorização específica; 0 arquivos de usuário versionados; 0 exceções não tratadas nos casos validados; 0 escrita cross-namespace nos testes; invariantes de schema e referências preservadas; reversão demonstrada; screenshot/layout de Studios revisado; comparações p50/p95 e RSS no mesmo hardware/fixture. Performance: iniciar com gate provisório de não regressão maior que **10% de p95** e **10% de pico RSS** em 20 repetições, com ruído/intervalos documentados; recalibrar após baseline, nunca proclamar melhora antes da medição. Nenhum gate substitui triagem humana dos diffs de UI.

## Sequência de primeiros PRs sugeridos

1. PR apenas de baseline + execução/documentação das auditorias existentes (`R-01`, `R-05`); sem tocar produto.
2. PR sandbox DEV AI inicial + fixture e teste de que dados reais não são acessados (`R-25`).
3. PR hardening Electron e contratos de storage em modo compatível (`R-06`, `R-07`).
4. PR isolamento shell/video com regressão antes/depois (`R-10`).
5. PR safe save/restore e lixeira (`R-08`, `R-09`), **antes** de migrar.
6. PR migração dry-run, depois migração opt-in (`R-15`–`R-17`).
7. PRs pequenas para extração de IPC/CSS/UI e otimização observada, priorizadas por risco e medida, não linhas de código.
